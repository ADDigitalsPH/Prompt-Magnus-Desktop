PRODUCT REQUIREMENTS DOCUMENT
Prompt Magnus Desktop

Version: 1.0
Product Type: Lightweight Desktop Application
Primary Platform: Windows-first desktop app
Future Platform Support: macOS optional after Windows MVP
Prepared for: Agent Builder / AI Development Agent


1. PRODUCT OVERVIEW

Prompt Magnus Desktop is a lightweight desktop prompt launcher that allows users to save reusable prompts and insert them into any active input field on their computer.

The core interaction is simple:

Press Ctrl + Space -> Search prompt -> Press Enter -> Prompt is pasted into the active app/input field.

The app should be useful for developers, AI users, creators, business owners, and anyone who repeatedly uses prompts inside tools like Codex, ChatGPT, Claude, Gemini, Notion, Slack, email clients, browser forms, document editors, and other desktop applications.

This is not a full AI writing app, not a prompt marketplace, and not a complex productivity dashboard. It is a small system-wide utility that runs in the background and helps users reuse prompts faster.


2. PRODUCT GOAL

The main goal is to help users save their best prompts once and insert them anywhere on their desktop without manually opening notes, documents, or old chats.

The app must be:

- Lightweight
- Fast
- Simple to use
- Keyboard-first
- Local-first
- Private
- Always accessible
- Useful even without internet
- Able to remain active in the background after the main window is closed


3. CORE VALUE PROPOSITION

Prompt Magnus Desktop helps users avoid repetitive copy-pasting by turning their saved prompts into a searchable desktop launcher.

Positioning:

"Save your best prompts. Press Ctrl + Space anywhere. Search. Press Enter. Paste instantly."

For users:

- No need to search inside Notion, Google Docs, text files, or old chat history.
- No need to copy and paste manually every time.
- No need to memorize long prompts.
- No need to keep the main app window open.
- The app stays available from the taskbar/system tray.

5. PRODUCT PRINCIPLES

5.1 Simplicity First

The app should do one job well: save prompts and insert them quickly.

Avoid unnecessary complexity in the MVP.

Do not include:

- AI generation
- Cloud sync
- Team collaboration
- Prompt marketplace
- Analytics dashboard
- Automation builder
- Prompt chain runner
- Login/account system
- Subscription billing
- Browser extension features

5.2 Launcher First

The launcher is the main product experience.

The user should not need to open the full app window often. The full app is mainly for saving, browsing, and editing prompts.

5.3 Local First

All prompt data should be stored locally on the user's device for the MVP.

The app should work offline.

5.4 Background Utility Behavior

The app should behave like a system utility.

When the user clicks the close button on the main window, the app should not fully quit by default. It should minimize to the system tray/taskbar area and continue running in the background.

The user should be able to reopen the app from the system tray/taskbar menu.

5.5 Clipboard-Based Prompt Insertion

The most realistic and compatible insertion method should be:

1. Save current clipboard content temporarily.
2. Copy selected prompt into clipboard.
3. Simulate Ctrl + V into the active input field.
4. Restore previous clipboard content after a short delay.

This keeps the app simple and compatible with most normal desktop input fields.

- Mark prompt as favorite

6.4 Save Prompt From Clipboard

Users can:

- Copy text from anywhere
- Press Ctrl + Shift + S

- Add title and category
- Save prompt

6.5 System Tray / Taskbar Behavior

The app must:

- Stay active after the window close button is clicked
- Continue listening for Ctrl + Space

8. USER FLOWS

8.1 Insert Prompt Into Active App

1. User opens any app.
2. User clicks an input field.
3. User presses Ctrl + Space.
4. Prompt Magnus Desktop launcher appears.
5. User types a search term.
6. Matching prompts appear.
7. User selects a prompt.
8. User presses Enter.
9. App temporarily copies selected prompt to clipboard.
10. App simulates Ctrl + V.
11. Prompt appears in the active input field.
12. App restores previous clipboard content.
13. Launcher closes.

8.2 Save New Prompt Manually

1. User opens Prompt Library.
2. User clicks + New Prompt.
3. New Prompt modal appears.
4. User enters title.
5. User selects category.
6. User enters prompt body.
7. User optionally marks as favorite.
8. User clicks Save.
9. Prompt appears as a card in the grid.

8.3 Edit Prompt

1. User opens Prompt Library.
2. User clicks a prompt card.
3. Edit Prompt modal appears.
4. User edits prompt details.
5. User clicks Save.
6. Prompt card updates.

8.4 Save Prompt From Clipboard

1. User copies prompt text from anywhere.
2. User presses Ctrl + Shift + S.
3. New Prompt modal appears.
4. Prompt body is pre-filled from clipboard.
5. User adds title and category.
6. User clicks Save.
7. Prompt is added to the library.

8.5 Close Window But Keep App Running

1. User clicks the X close button on the main window.
2. Main window closes or hides.
3. App remains active in the system tray/taskbar.
4. Ctrl + Space still opens the launcher.
5. User can right-click tray icon and reopen the Prompt Library.

13. PROMPT INSERTION METHOD

The app should use clipboard-based insertion.

Process:

1. Detect selected prompt.
2. Store current clipboard content in memory.
3. Set clipboard content to prompt body.
4. Simulate paste command:
   - Windows: Ctrl + V
   - macOS future support: Cmd + V
5. Wait briefly.
6. Restore previous clipboard content.
7. Close launcher.

Important:

- The app should avoid permanently replacing the user's clipboard.
- If clipboard restoration fails, the app should not crash.
- If paste fails, the app may show a small error message.


14. SYSTEM TRAY BEHAVIOR

- On app startup, initialize tray icon.

- User can add a custom category.
